# 从 TAAC 2025 迁移什么，如何验收

来源为 [TAAC 2025 官方论文](https://arxiv.org/abs/2604.04976)，任务介绍见[论文笔记](../../papers/taac2025.md)。本页只讨论迁移设计，不能用论文中的 2025 成绩证明当前 PCVR 效果。

## 先确定输出目标

候选召回回答“从大量物品中取哪些”，PCVR 回答“给定输入的正类概率是多少”。二者的数据组织、负样本、损失、索引与指标都不同。统一 token 表达可以共享，但评测闭环不能省略。

## 可以优先迁移的局部问题

| 启发 | 本项目中的可检验问题 |
| --- | --- |
| 多行为条件 | 不同行为域/类型是否有独立贡献 |
| 内容与协同联合表示 | 当前 schema 若具备内容信息，是否改善低频或新物品 |
| 序列规模化 | 扩大历史预算是否优于增加模型宽度 |
| 负样本与排序目标 | 在相同标签数据下，辅助排序是否改善验证排序 |

先确认字段可用与时间合法性，再设计单变量实验。没有文本/图像输入时不能把普通 dense 字段直接称作多模态内容。

## 完整生成式路线还缺什么

Semantic ID/codebook、候选编码、ANN 或离散解码、合法候选约束、召回评估与线上输出适配均需明确实现。当前共享 PCVR 框架没有这些完整链路，不能只新建模型包就宣称生成式推荐部署完成。

## 验收顺序

先用小规模候选集验证输入到检索输出的真实闭环，再检查标识覆盖、碰撞、空候选和 Top-K 合法性；在独立时间数据上比较质量、召回延迟与索引成本。最后评估能否与当前概率提交契约连接，不能用内部 proxy 指标替代比赛要求。

源数据与官方 baseline 链接见[论文资源](../../papers/taac2025.md)。任何迁移收益都需本项目实测。
